# Bulk pipeline pattern — author + render + queue 100 shorts

**Established 2026-05-08** for Cosmos Decoded; reusable across any
channel that wants a multi-week upload backlog.

## Pattern

```
subject_list_100.json   →   bulk_author_100.py   →   bulk_render_100.py   →   cron_upload_daily.py
   (curated)             (claude CLI batch)        (Cloud Run + ffmpeg)       (10/day, every 2hrs)
```

Three scripts under `<channel>/scripts/`, one cron entry.

## Step 1 — subject list

`<channel>/scripts/subject_list_100.json`

Schema (one entry per subject):

```json
{
  "<category>": [
    {
      "slug": "kebab-case-id",
      "title": "Display title — what changed",
      "thesis": "One-sentence what was measured and what it implied"
    }
  ]
}
```

For Cosmos Decoded the curation rule was: every subject is a
**moment of measurement** — single empirical event with date,
person/team, instrument. Theoretical proposals (Newton's Principia)
and inventions (first laser) without an empirical-confirmation step
are weaker fits — pick subjects with `prediction → measurement →
consequence` arc.

## Step 2 — bulk_author_100.py

Two LLM calls per subject (parallelised across `--workers N`):

1. **Narration** — 6-beat structure, ~130 words, ends with literal
   closer "SUBSCRIBE for more decoders. LIKE if this changed how you
   see physics."
2. **Shotlist** — 18-21 windows, premium-cadence ~2.66s/cut, every
   window unique `source_url`. The shotlist's `_ai_image_prompts`
   block describes any AI image referenced — these get generated by
   the bulk-render orchestrator just-in-time.

Uses `pipeline.llm.cli.call_claude_cli` (no API key — OAuth via
Claude Code keychain). Budget cap **bumped to $2.00/call** because
shotlists are 4-8KB JSON; default $0.50 hits the cap.

**Post-processing in author_one():** model often returns `in_s/out_s`
as cumulative video timestamps (e.g. `[3.0, 6.0, 8.7, 11.4, ...]`)
instead of per-clip duration (`[3.0, 3.0, 2.7, 2.7, ...]`). The script
detects and converts.

**Wallclock:** ~150-200s per subject serial; ~40 min for 100 with
workers=6.

**Failure mode (observed):** at the tail end of a long parallel run,
the `claude` binary lookup intermittently fails with
`OSError: [Errno 8] Exec format error: 'claude'` or `FileNotFoundError`.
Cause unknown — likely subprocess inheritance of env vars. **Mitigation:**
re-run with `--force` or just retry the failed slugs serially; works
on retry.

## Step 3 — bulk_render_100.py

For each pending slug (has narration+shotlist, no mp4 yet):

1. **Just-in-time AI image gen** via `pipeline.images_cloudrun
   ._generate_cloudrun_flux2_klein` — reads the slug's
   `<slug>.ai_prompts.json` and generates any missing PNGs
   (8-way parallel within the slug). Avoids burning $20 of GPU
   upfront for images that may never be rendered if the queue is
   trimmed.
2. **`pipeline.cosmos_footage_prep`** — fetches Wikimedia stills,
   ken-burns to per-window mp4s.
3. **`historyrecapped/scripts/render_footage_only.py
   --channel <channel> --slug <slug>`** — concat, mux narration,
   burn captions.

**Concurrency:** `--workers 3` is the safe sweet spot. workers=4
stresses Cloud Run with `~80 simultaneous /generate calls` (3 renders
× ~25 image gens each).

**Wallclock:** ~80-160s per render with workers=3 = **45-60 min for
100 shorts** wall-clock if Cloud Run autoscale stays warm.

## Step 4 — cron_upload_daily.py

Cron entry:

```cron
0 9,11,13,15,17,19,21,23,1,3 * * * /path/to/.venv/bin/python \
    /path/to/<channel>/scripts/cron_upload_daily.py \
    >> /path/to/<channel>/cron_upload.log 2>&1
```

**10 slots/day at 2-hr intervals** from 9am IST (9, 11, 13, 15, 17,
19, 21, 23, 01, 03 IST). Each cron firing uploads ONE pending mp4
and schedules its public release for the NEXT IST cron slot via
YouTube's `status.publishAt` API. Pending = mp4 exists, no upload
record yet.

**Why scheduled-public not immediate-public:** YouTube's algorithm
seems to prefer videos that age in `private/scheduled` state for at
least a few hours before going public — gives the recommendation
graph time to compute features.

## Cron-pattern math

100 shorts ÷ 10/day = **10-day backlog drain**.

If you author + render the next 100 in parallel during day 1, day 11
is when you start needing a fresh batch. Plan content authoring on a
2-week cadence.

## Channel applicability

This pattern is **channel-agnostic**. To clone for another channel:

1. Author `subject_list_100.json` for that channel's wedge.
2. Adapt `bulk_author_100.py` prompts to that channel's
   beat-structure / closer / vocabulary rules.
3. `bulk_render_100.py` is mostly reusable — just change the
   `channel` argument and the AI-image-prefix convention.
4. `cron_upload_daily.py` is reusable — change the channel name in
   the upload call.
